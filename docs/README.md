# UniAgent 设计文档索引

本目录是《基于 Agent 的大学生综合工作台系统的设计与实现》的设计基线。文档只描述当前有效方案；过期方案不保留在主文档中，历史变化由 Git 记录。

## 阅读顺序

1. [01-课题规划.md](01-课题规划.md)：了解研究背景、问题、范围、创新点和实验方向。
2. [02-课题设计.md](02-课题设计.md)：了解系统目标、架构、组件边界和关键设计决策。
3. 按需进入专项文档，获取可实现和可验证的详细定义。

## 唯一事实来源

为避免多个文档重复定义后发生漂移，以下内容只在指定文档中维护详细版本：

- 课题题目、研究问题、业务范围和创新点：`01-课题规划.md`；
- 系统架构和组件边界：`02-课题设计.md`；
- 用例编号、优先级和验收口径：`04-需求规格与验收.md`；
- BPMN、业务状态、ER 和事务一致性：`05-流程与数据模型.md`；
- 工具名称、参数、权限、确认和错误码：`06-Agent工具与权限契约.md`；
- Agent 运行状态、证据等级、审查降级和全链路追踪：`07-Agent稳定执行与全链路监督.md`。

其他文档可以概括这些内容并引用事实来源，但不复制完整枚举、字段和规则。

## 维护规则

- 课题范围或核心决策变化时，同步更新 `01` 和 `02`，再更新受影响的专项文档；
- 专项规则变化时，只修改其唯一事实来源，并检查 `02` 中的概括是否仍然准确；
- 新增文档必须有独立职责，不能只是现有文档的改写或摘要；
- 流程图、ER 图、时序图优先使用 Mermaid，与解释文本放在对应专项文档；
- 文档使用当前时态，不记录“原来、调整为、暂时、后续重写”等过程措辞；
- 不在主文档中保留废弃方案或占位报告，历史通过 Git 提交查询；
- 正式开题报告、论文和答辩材料在内容成熟后作为独立交付物加入索引。

## 变更检查

每次重要设计更新至少检查：

1. 是否仍符合课题名称和研究问题；
2. 是否超出既定业务范围；
3. Agent 是否绕过工具网关、人工确认或审批责任；
4. 需求、流程、状态、工具与权限是否一致；
5. 是否有可测试的验收条件和可追溯证据；
6. 是否产生了与现有文档职责趋同的新文档。
