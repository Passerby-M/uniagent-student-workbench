# UniAgent（大学生综合工作台）课题规划

## 1. 课题名称

**基于 Agent 的大学生综合工作台系统的设计与实现**

英文名称：Design and Implementation of an Agent-Based Integrated Workbench for University Students。

## 2. 研究背景

大学生办理请假、销假、奖助学金、证明和活动申请等校园事务时，常面临事项入口分散、制度术语难以理解、材料反复补交和流程状态不透明等问题。传统网上办事大厅主要依赖菜单检索和固定表单，要求学生事先了解事项名称、主管部门和办理规则。

UniAgent 以自然语言 Agent 作为统一交互与任务协助入口，以工作流引擎作为正式业务的可靠执行基础。学生可以直接描述目标，Agent 负责识别事项、检索制度、收集信息、生成表单草稿、检查材料和解释流程；Flowable 负责提交后的任务分配、条件分支、人工审批、状态管理和操作留痕。

## 3. 研究目标

本课题研究 Agent 如何在受控边界内连接制度知识、学生数据、事项表单和工作流工具，并完成以下目标：

1. 建立面向学生校园事务的自然语言统一入口；
2. 实现事项识别、必要信息澄清、任务规划和受控工具调用；
3. 使用版本化制度知识支持可引用、可拒答的规则解释；
4. 通过工作流实现申请、审批、退回、撤回、销假和归档闭环；
5. 通过授权、确认、审查、降级和审计控制 Agent 的不确定性；
6. 形成覆盖会话、模型、检索、工具、业务和审批的全链路追溯；
7. 对比传统菜单办理和 Agent 协助办理的质量、效率与用户负担。

## 4. 研究问题

- RQ1：如何从学生的自然语言请求中稳定识别校园事项、办理动作和必要参数？
- RQ2：如何根据用户目标、事项类型和流程节点选择有效制度知识与业务工具？
- RQ3：如何将 Agent 生成的计划和草稿安全转换为可验证的工作流操作？
- RQ4：如何通过权限、确认、证据审查、结果核验和降级机制约束错误与越权？
- RQ5：如何监督完整业务链路，并定位任一申请的 Agent 决策、工具执行和流程状态？
- RQ6：与传统菜单和表单相比，Agent 工作台能否提高事项发现、材料准备和流程查询效率？

## 5. 业务范围

### 5.1 深度流程：请假与销假

覆盖事项咨询、规则解释、对话式填表、材料预审、学生确认提交、辅导员审批、条件触发学院审批、退回修改、审批前撤回、请假生效、销假确认和办结归档。

该流程用于验证 Agent 从意图理解到工作流执行的完整闭环，以及权限、确认、幂等、降级和追溯机制。

### 5.2 重点 Agent 场景：奖助学金申请

覆盖政策问答、资格初筛、材料清单生成、证明材料一致性检查、申请摘要和评审辅助。系统仅解释制度和提示可能性，不替代正式资格认定或人工评审。

### 5.3 模板化场景

- 在读证明、成绩证明等证明申请；
- 学生活动或场地申请；
- 就业手续和其他校园办事指南。

模板化场景用于验证事项目录、通用表单和工作流模型的扩展能力，不建设完整的专业业务子系统。

## 6. Agent 能力范围

| 业务阶段 | Agent 能力 | 连接资源 | 控制点 |
| --- | --- | --- | --- |
| 事项发现 | 理解目标、召回候选事项、解释条件 | 事项目录、制度知识 | 学生选择正式事项 |
| 信息收集 | 多轮澄清、授权资料复用、表单草拟 | 表单定义、学生资料 | 字段级授权与学生核对 |
| 提交前 | 规则校验、语义一致性检查、材料建议 | 校验规则、附件、制度条款 | 学生决定修改或提交 |
| 流程中 | 查询状态、解释节点、提示下一步 | 工作流查询、通知 | Agent 不改写流程状态 |
| 审批中 | 生成摘要、整理依据、标记待核验项 | 申请版本、审批历史 | 审批人员独立决定 |
| 办结后 | 生成摘要、标签和归档建议 | 流程记录、材料清单 | 规则校验或管理员确认 |
| 日常咨询 | 回答学籍、奖助和就业制度问题 | RAG 知识库 | 显示引用，无依据时拒答 |

## 7. 角色与责任

- 学生：咨询、办理、授权资料使用、核对并确认提交、撤回、销假、查询和评价建议；
- 辅导员：处理管辖范围内的审批和材料核验；
- 学院管理员：处理学院级任务，维护事项、制度和档案；
- 系统管理员：管理账号、角色、流程部署、工具权限和模型配置；
- Agent：承担理解、规划和辅助，不作为拥有独立审批权的业务角色。

## 8. 研究边界

- 不接入真实高校统一身份、教务、财务和学工生产系统；
- 不处理真实资金发放、学籍变更、处分决定和电子签章；
- 不训练或微调基础大模型；
- 不允许 Agent 自主审批或绕过学生确认提交；
- 不建设覆盖全校全部制度和事项的生产级知识库；
- 不引入与研究问题无关的微服务、复杂消息系统和大屏展示；
- 开发和实验使用虚构、公开或脱敏数据。

## 9. 技术路线

- 前端：Vue 3、TypeScript、Vite、Element Plus、Pinia；
- 后端：Java 21、Spring Boot 3、Spring Security、Spring Data JPA；
- 工作流：Flowable 7、BPMN 2.0；
- 数据库：H2 用于本地开发，PostgreSQL 用于部署与实验；
- Agent：OpenAI 兼容模型、结构化输出、任务状态机和工具调用；
- 知识增强：制度版本管理、混合检索、引用与拒答；
- 监督：事务事件、审计账本、OpenTelemetry 和一致性巡检；
- 测试：JUnit 5、MockMvc、Testcontainers、Vitest；
- 部署：Docker Compose。

系统采用模块化单体。Agent 通过受控工具网关访问业务能力，不直接访问数据库或 Flowable 内部表。

## 10. 预期创新点

1. 设计“Agent 交互与任务协助层—确定性业务与工作流执行层”的双层协同结构；
2. 根据学生目标、事项类型和流程节点动态组装最小必要上下文；
3. 将版本化制度证据、结构化计划、受控工具和结果验证组合为稳定执行闭环；
4. 使用工具白名单、资源级授权、二次确认和全链路审计约束 Agent 操作；
5. 建立会话、模型、检索、工具、业务事务和工作流任务之间的统一追溯关系；
6. 通过基线实验、消融实验和安全测试评价 Agent 的实际作用与适用边界。

这些创新属于面向校园事务的系统设计、机制组合和实验验证，不涉及基础模型或工作流理论创新。

## 11. 实验方向

- 事项导航：评价 Top-1 准确率、Top-k 召回率、澄清有效率和错误路由率；
- 对话式办理：比较任务完成率、完成时间、交互步骤、字段错误和补交次数；
- 材料预审：评价 Precision、Recall、F1、误报率和问题定位准确率；
- 制度问答：评价答案正确率、引用正确率、无依据拒答率和幻觉率；
- 工具安全：评价越权、缺确认、重复调用和提示词注入的拦截率；
- 稳定性：评价模型故障降级、写操作状态核验和业务流程可用性；
- 可追溯性：验证单个申请能否重建完整关键时间线；
- 消融实验：移除节点上下文、制度检索或确定性规则，观察性能变化。

## 12. 预期成果

- UniAgent 原型系统及可部署源代码；
- 请假/销假完整 BPMN 和模板化业务流程；
- 事项导航、对话填表、材料预审和制度问答 Agent；
- 受控工具网关、审查降级与全链路监督机制；
- 可复现的实验数据、标注规范、测试结果和分析图表；
- 课题设计、开题报告、毕业论文和答辩材料。
