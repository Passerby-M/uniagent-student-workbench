# FacultyFlow（智流教师工作台）课题规划

## 1. 研究目标

面向高校教师事务分散、流程状态不透明、制度查询成本高和归档依赖人工等问题，设计并实现一个以工作流为主线、以 Agent 为辅助的综合工作台。系统覆盖“申请—预审—人工审批—归档—检索”闭环。

## 2. 首版范围

- 深度实现：请假/出差申请，包括草稿、材料预审、提交、分级审批、撤回、办结和归档。
- 模板化实现：科研项目、教学任务和报销申请复用统一申请与流程模型，可配置表单和审批链。
- 横向能力：统一待办、流程跟踪、站内通知、制度知识库问答和档案检索。
- 角色：教师、系主任、学院管理员、系统管理员。

## 3. Agent 设置

1. 材料预审 Agent：检查字段完整性、材料缺失和制度冲突，给出建议，不替用户提交。
2. 审批辅助 Agent：汇总申请内容、历史节点与风险点，不自动作出通过或驳回决定。
3. 制度问答 Agent：基于制度文档检索增强生成，回答中返回引用来源。
4. 归档 Agent：生成摘要、关键词、分类和保管期限建议，由规则校验后入库。

所有 Agent 输出均保存模型、提示词版本、引用、耗时及人工采纳结果，便于审计和论文实验。

## 4. 技术架构

- 前端：Vue 3、TypeScript、Vite、Element Plus、Pinia。
- 后端：Java 21、Spring Boot 3、Spring Security、Spring Data JPA。
- 工作流：Flowable 7，BPMN 2.0 流程定义。
- 数据库：开发阶段使用 H2，部署与实验使用 PostgreSQL。
- 大模型：OpenAI 兼容接口，通过环境变量配置；无密钥时支持确定性 Mock。
- 部署：Docker Compose，后续加入 PostgreSQL 和前后端镜像。

## 5. 可论证的创新点

- 工作流状态与 Agent 上下文联动：按流程节点组装最小必要上下文，减少无关信息和越权风险。
- 人机协同审批机制：Agent 只做预审、摘要与建议，关键决策保留人工确认，并记录采纳反馈。
- 面向闭环的智能归档：利用流程数据自动形成可追溯档案元数据，连接业务办理与知识复用。

## 6. 实验设计

- 材料预审：构造完整、缺字段、缺附件、制度冲突等样本，评估准确率、召回率和 F1。
- 审批摘要：由教师或模拟评审按完整性、忠实性、可用性进行五级评分。
- 制度问答：评估回答正确率、引用命中率和无依据回答率。
- 效率对比：对比无 Agent 与有 Agent 两组的填写耗时、审批阅读耗时、退回率。
- 系统测试：功能、权限、并发响应时间及核心后端代码覆盖率。

## 7. 论文结构

1. 绪论
2. 相关技术与理论基础
3. 系统需求分析
4. 系统总体设计
5. 系统详细设计与实现
6. 系统测试与 Agent 效果评估
7. 总结与展望

## 8. 里程碑

- M1：需求、用例、架构、数据模型和流程模型。
- M2：登录、工作台、申请与 Flowable 审批闭环。
- M3：四类 Agent、知识库和智能归档。
- M4：测试数据、对照实验、性能测试和结果分析。
- M5：论文初稿、图表、查重前修改与答辩材料。
