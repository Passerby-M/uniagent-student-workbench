# UniAgent Agent 工具与权限契约

## 1. 信任边界

Agent 只能调用白名单工具，不能直接访问数据库、Flowable 内部表、审批接口、通用 HTTP 或 SQL 工具。身份、角色、组织范围和授权结果由服务端认证上下文注入，模型不得提供或覆盖。

允许调用必须同时满足：工具已授权、用户已认证、角色允许、资源属于授权范围、业务状态允许、参数符合 Schema、敏感字段已授权、关键写操作具有有效确认凭证。

## 2. 工具等级

| 等级 | 类型 | 示例 | 控制 |
| --- | --- | --- | --- |
| L0 | 公开只读 | 事项、公开制度检索 | 无操作确认 |
| L1 | 受限只读 | 本人资料、本人流程 | 资源与字段授权 |
| L2 | 只读计算 | 规则校验、确认挑战 | 不改变正式状态 |
| L3 | 可逆写入 | 保存草稿 | 本人资源、版本和幂等 |
| L4 | 关键写入 | 提交、撤回 | 可信界面二次确认 |
| L5 | 人工决定 | 通过、退回、拒绝 | 禁止 Agent 调用 |

## 3. 通用契约

请求包含 `tool_call_id`、`session_id`、严格 Schema 的 `arguments`，写操作另含 `idempotency_key`，关键写操作另含 `confirmation_token`。

`actor_user_id`、角色、组织范围、访问令牌、授权结论、IP 和服务端时间均由后端注入，不对模型开放。

响应统一包含 `success`、`data`、`error` 及 `request_id`、执行时间、数据分类、脱敏字段、授权策略版本和是否幂等重放等元信息。

## 4. 确认机制

`request_user_confirmation` 只创建待确认挑战，不执行业务动作。服务端根据资源当前快照生成确认摘要，可信 UI 展示事项、关键字段、警告和目标动作。

确认凭证必须绑定用户、会话、动作、资源、资源版本、参数摘要、过期时间和一次性随机数。普通聊天中的“确认”“可以”不能替代可信界面事件。草稿修改、凭证过期或消费后，凭证立即失效。

## 5. 工具清单

### 5.1 search_matters（L0）

请求：查询文本、类别、校区、分页、是否返回表单模式。

响应：事项 ID、名称、说明、资格摘要、材料要求、流程概览、制度引用和可办理状态。

控制：只返回已发布事项；不暴露内部办理人、表达式和未发布配置。

### 5.2 search_policies（L0/L1）

请求：问题、事项、有效时间、范围和 `top_k`。

响应：可回答状态，以及文档、版本、条款位置、片段、来源和相关度。

可回答状态为 `SUPPORTED`、`PARTIAL`、`NOT_FOUND` 或 `CONFLICTING`。制度片段统一标记为不可信数据，片段中的命令不得改变系统规则或触发工具。

### 5.3 get_student_profile（L1）

请求：用途、事项、字段代码和敏感字段授权编号，不允许传入学生 ID。

响应：授权字段、来源、数据分类及拒绝字段原因。

控制：服务端只解析当前学生本人；字段必须在当前事项最小化白名单中；健康、家庭经济和身份证件等字段需要字段级授权；禁止通配符和整档读取。

### 5.4 validate_application（L2）

请求：事项与草稿版本，或符合表单 Schema 的数据及本人附件引用。

响应：规则集版本、错误、警告、制度引用和是否满足提交条件。

控制：只执行确定性规则；输出是提交前检查，不作审批或资格认定。

### 5.5 save_draft（L3）

请求：事项、草稿 ID（新建时为空）、期望版本、表单数据和附件引用。

响应：草稿 ID、申请编号、最新版本、保存时间和校验摘要。

控制：只能维护本人草稿或退回待修改申请；使用乐观锁和幂等键；不得将 Agent 自由文本直接写入结构化字段。

### 5.6 submit_application（L4）

请求：草稿 ID、草稿版本、确认凭证和幂等键。

响应：申请编号、业务状态、流程实例编号、当前节点和提交时间。

控制：后端重新执行完整校验并验证确认摘要；只允许 `READY` 状态；相同幂等键返回原结果；Agent 不能自行生成确认凭证。

### 5.7 query_process（L1）

请求：申请 ID 或申请编号，以及详情范围。

响应：业务状态、当前节点、可执行动作和脱敏流程轨迹。

控制：学生仅查询本人申请；审批人员仅查询本人任务或管辖范围；不能仅凭模型提供的流程实例 ID 授权。

### 5.8 withdraw_application（L4）

请求：申请 ID、申请版本、撤回原因、确认凭证和幂等键。

响应：最终状态与撤回时间。

控制：仅申请人可操作，且状态限于 `IN_REVIEW` 或 `RETURNED`；后端检查活动节点并关联中断消息；已生效流程不能撤回。

### 5.9 request_cancellation（L4）

请求：已生效申请 ID、实际返校时间、说明、确认凭证和幂等键。

响应：`CANCELLATION_PENDING` 状态和辅导员待办概览。

控制：仅本人、仅 `EFFECTIVE` 状态，重复请求只产生一个有效销假流程动作。

## 6. 错误码

| 错误码 | 含义 |
| --- | --- |
| `AUTHENTICATION_REQUIRED` | 未登录或会话失效 |
| `FORBIDDEN` | 角色、组织或资源权限不足 |
| `RESOURCE_NOT_FOUND` | 资源不存在或为防枚举统一隐藏 |
| `VALIDATION_FAILED` | 参数或业务规则未通过 |
| `INVALID_STATE` | 当前业务或流程节点不允许操作 |
| `VERSION_CONFLICT` | 草稿或申请版本已变化 |
| `CONFIRMATION_REQUIRED` | 缺少关键操作确认 |
| `CONFIRMATION_INVALID` | 确认过期、不匹配或已消费 |
| `IDEMPOTENCY_CONFLICT` | 相同幂等键对应不同参数 |
| `POLICY_EVIDENCE_NOT_FOUND` | 制度依据不足 |
| `MODEL_UNAVAILABLE` | 模型超时或不可用，可降级 |
| `TOOL_NOT_ALLOWED` | 工具不在当前 Agent 白名单 |
| `UNSAFE_CONTENT` | 检测到注入或危险内容 |

错误响应不返回其他用户是否存在、数据库结构、堆栈、权限规则源码、令牌或密钥。

## 8. 审计要求

每次工具调用记录调用编号、会话、用户、角色快照、工具、参数摘要哈希、目标资源、授权结果、确认编号、幂等键、模型与 Prompt 版本、制度引用、耗时、结果状态和错误码。

普通日志不得记录密码、Token、模型密钥、完整身份证号、健康或家庭经济信息及附件全文。

## 9. Prompt 注入防护

- 用户输入、制度片段、附件文本和工具结果都作为不可信数据；
- 系统指令与工具 Schema 不从检索内容动态生成；
- 未声明字段一律拒绝，身份与授权字段由服务端覆盖；
- Agent 不具备通用网络、文件、SQL 和流程引擎访问能力；
- 工具网关独立鉴权，不能信任模型关于“用户已授权”的陈述；
- 涉及写操作时，服务端重新读取资源并校验版本与确认摘要；
- 注入测试、越权测试和危险参数测试纳入 P0 验收。
