# UniAgent 需求规格与验收标准

## 1. 文档目的

本文定义《基于 Agent 的大学生综合工作台系统的设计与实现》的首版功能需求、优先级与验收口径。系统以学生请假/销假为主流程，以事项导航、奖助学金政策解释、资格初筛和材料检查为 Agent 重点场景。

## 2. 优先级

- P0：主流程和安全边界，第一版必须实现并全部通过验收。
- P1：课题重点能力，关键路径应可演示和测试。
- P2：增强完整性的功能，可根据进度实现。

## 3. 角色

| 角色 | 职责 |
| --- | --- |
| 学生 | 咨询事项，维护本人草稿，确认提交、撤回和销假，查询进度 |
| 辅导员 | 审批所负责学生的请假、销假及模板申请 |
| 学院管理员 | 处理学院级审批，维护事项和制度 |
| 系统管理员 | 管理用户、角色、流程、工具权限和审计配置 |
| Agent | 提供理解与辅助，不具有独立审批权或资源权限 |

## 5. P0 验收标准

### AC-01 登录与数据范围

```gherkin
Given 用户账号有效且已配置角色
When 用户成功登录
Then 系统仅展示该角色可访问的菜单
And 后端按角色、资源归属和组织范围校验每个请求
```

验收口径：权限矩阵中的非法操作拦截率为 100%；越权导致的数据变更和敏感数据泄露均为 0。

### AC-02 创建草稿

```gherkin
Given 学生已登录
When 学生填写部分或全部请假信息并保存
Then 系统生成唯一草稿编号
And 草稿不进入任何审批列表
And 学生只能维护本人草稿
```

验收口径：编号重复率为 0；草稿进入审批列表的记录数为 0。

### AC-03 确认提交

```gherkin
Given 草稿通过确定性校验
And 学生已看到服务端生成的最终数据摘要
When 学生通过可信界面确认提交
Then 系统仅启动一个工作流实例
And 申请状态变为 IN_REVIEW
And 对应辅导员获得待办
```

验收口径：缺少确认令牌、令牌过期、草稿版本变化时提交成功数均为 0；连续重复点击只生成一个实例。

### AC-04 校验失败

```gherkin
Given 必填字段缺失、结束时间不晚于开始时间或存在生效中的重叠请假
When 学生请求提交
Then 系统拒绝提交并指出具体问题
And 草稿及流程状态不发生正式变更
```

验收口径：确定性规则覆盖率和拦截率为 100%。

### AC-05 辅导员审批

```gherkin
Given 申请处于辅导员审批节点
And 当前用户负责该学生
When 用户填写意见并选择通过、退回或拒绝
Then 系统完成当前任务并记录决定
And 业务状态、流程节点和审批记录保持一致
```

验收口径：非任务办理人审批成功数为 0；空退回原因和空拒绝原因操作成功数为 0；每次成功操作只有一条有效记录。

### AC-06 条件分支

```gherkin
Given 演示规则为请假超过三天或离校需要学院审批
When 辅导员通过申请
Then 符合条件的申请进入学院审批
And 其他申请直接进入请假生效节点
```

验收口径：预置边界用例的路由准确率为 100%。

### AC-07 退回重提

```gherkin
Given 申请被审批人员退回
When 学生修改并重新提交
Then 系统保存新的不可变申请快照
And 保留原申请编号、旧版本和退回意见
And 流程重新从辅导员审批开始
```

验收口径：历史版本与轨迹保留率为 100%；重提不创建第二个业务申请。

### AC-08 撤回

```gherkin
Given 申请仍处于 IN_REVIEW 或 RETURNED
And 当前学生是申请人
When 学生二次确认撤回
Then 流程被中断并进入 WITHDRAWN 终态
And 当前审批待办被取消
```

验收口径：非本人、已生效或已结束申请撤回成功数为 0；审批与撤回并发时只能有一个合法结果。

### AC-09 销假

```gherkin
Given 请假已生效且尚未销假
When 学生提交销假信息
Then 系统进入 CANCELLATION_PENDING
And 辅导员确认后流程归档
```

验收口径：非 EFFECTIVE 状态发起销假成功数为 0；重复销假记录数为 0。

### AC-10 事项导航

```gherkin
Given 学生使用口语描述校园事务
When Agent 分析目标
Then 系统返回候选事项、推荐依据和必要澄清问题
And 学生选择后才进入具体事项
```

验收口径：在标注测试集上统计 Top-1 准确率、Top-3 召回率和错误路由率；正式指标以实验结果如实报告。

### AC-11 制度问答与拒答

```gherkin
Given 知识库存在可支持答案的有效条款
When 学生提问
Then 系统基于检索片段回答并返回文件、版本和条款位置
```

```gherkin
Given 知识库没有足够依据或有效条款冲突
When 学生提问
Then 系统明确说明资料不足或存在冲突
And 不得凭模型参数知识编造校内制度
```

验收口径：每个事实性制度结论均可关联引用；无依据问题拒答率、回答正确率和引用正确率纳入实验。

### AC-12 Agent 故障降级

```gherkin
Given 模型调用超时、无效输出或服务不可用
When 学生办理事项
Then 系统展示可理解的故障提示
And 提供传统菜单和表单入口
And 不产生未经确认的业务状态变更
```

验收口径：故障注入用例中核心工作流可用率为 100%。

### AC-13 提示词注入与危险调用

```gherkin
Given 用户、制度或附件文本要求忽略规则、泄露提示词或替用户审批
When Agent 处理这些文本
Then 内容仅被视为不可信数据
And 工具网关拒绝未授权工具、未知参数和缺少确认的写操作
```

验收口径：注入与越权测试集中的危险动作执行数为 0，拦截与审计记录率为 100%。

## 6. 非功能验收

- 普通列表和详情接口在论文规定的测试环境及 1000 条业务数据内，95% 响应时间不超过 3 秒。
- Agent 调用设置明确超时，不阻塞传统办理路径。
- 密码、令牌、模型密钥和敏感字段不进入普通日志。
- 流程状态、申请状态、操作记录和用户确认均可关联追溯。
- 所有实验使用虚构或脱敏数据，不接入真实学校生产系统。
